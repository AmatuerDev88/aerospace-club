# Choose a first project by the question it answers

The first project should produce a reproducible measurement within a school term and leave reusable knowledge behind. A vehicle is optional. A clear question, available supervision, and a way to validate the result are essential.

| Candidate investigation | Useful question | Evidence needed before choosing |
| --- | --- | --- |
| Sensor characterization on a bench | Can we quantify drift or repeatability over the intended range? | Available sensor and reference instrument; agreed error budget |
| Telemetry link on a controlled bench | Can we measure missing and delayed records reliably? | Chosen devices, sequence-counter behavior, permitted operating setup |
| Simulation with verification cases | Does the model reproduce a known limiting case? | Explicit assumptions, analytic reference, measurable error criterion |
| Balloon, rocket, or drone feasibility study | What constrains a safe and achievable mission? | Faculty sponsor, operating constraints, recovery plan, costs, and jurisdiction-specific review |

These are candidate studies, not selected hardware or promised capabilities.

Before buying parts, each proposal should answer: who needs the result, what can be demonstrated with current resources, how correctness will be checked, and what happens if the main assumption is wrong. Use the [project brief](../templates/project-brief.md). Compare cost, learning value, supervision needs, uncertainty, and available time in a meeting; do not hide a deal-breaking constraint inside a numerical score.

Record the selected option and reasons in a decision record. Start with one project owner and one reviewer, plus a faculty sponsor for physical work. Use roles in public records unless members have agreed to publish names. Purchase decisions, legal requirements, and flight authorization remain outside this starter repository; verify them for the actual activity and location when a project is selected.
